# Candidate actions before sending the IncuBrix PS2 submission

This build is a locally tested project archive, not a hosted final submission. Complete these account- and candidate-specific actions before sending anything to IncuBrix:

1. **Review and understand the project.** Read `README.md`, `REPORT.md`, `SOURCES.md`, `AI_USE.md`, `app/timeline.py`, `app/engine.py`, and `app/render.py`. The assessment includes a live explanation/debug/change session; do not submit code you cannot explain. Keep `AI_USE.md` truthful and add any other tools you used.
2. **Run it on your own machine.** Install Python 3.11+, FFmpeg and FFprobe; follow the local Quick Start. Run `python -m pytest -q` and the session runner. The current container result was 56 passing tests. Docker was unavailable in the build environment, so validate `docker compose up --build` yourself before marking it as verified.
3. **Use real, rights-cleared evidence.** The checked-in video contains a generated tone and no speech. Make a new test using a talking-head video you own or have explicit permission to use, plus a commercially usable music track. Keep the transcript, outputs and logs. Do not use a person's voice/face/content without consent.
4. **Create the private GitHub repository from your account.** Push the reviewed project with meaningful commit history (for example, separate commits for timeline/engine, parser, renderer, API/UI, and tests/docs). Invite `techteam@incubrix.com` with reviewer access. Replace the repository placeholder in the workbook with the real URL.
5. **Deploy and verify the live demo.** Host the API and browser studio, set non-default secrets through the host's secret settings, restrict access or add an access token, apply a rate limit, and test the public URL from a fresh browser. The project uses in-memory job/session state, so use a single worker for this MVP; do not claim durable multi-worker production readiness.
6. **Record the unedited demo video.** Use `DEMO_RECORDING_SCRIPT.md`; keep it within the requested 8 minutes. Record the actual application and tests, not a fabricated or edited screen capture. Link the recording in the workbook.
7. **Finish the workbook.** Replace every `NOT DEPLOYED` / `NOT CREATED` / `NOT RECORDED` placeholder with real links after doing those tasks. Enter actual time spent and actual machine details. Reassess statuses after testing on your own footage. Complete every statement on `7_Declaration`, enter your full name and date, and sign only if every declaration is true.
8. **Final pre-send check.** Confirm every submitted URL works without your logged-in browser, reviewer access is granted, the demo video is unedited, the test pack includes failures as well as successes, and the report contains only numbers you measured.

Do not submit the current workbook unchanged: it deliberately leaves the personal declaration unsigned and accurately marks the live demo, GitHub repository, Docker verification and recording as incomplete.
